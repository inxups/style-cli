按任务记录中的“设计项先回写相关 docs/spec，用户评审通过后进入实现”，本轮只形成契约、规范入口和 A9 断言。D4 更新为 `[~]`；T40/A9 不关闭，真实 B3/C5 保持 `[?]`。M3 其他阶段仍沿当前依赖顺序推进，未删除任何 backlog。

源码调查得到以下事实，可由报告中的文件摘要和基线命令复核：

- [state.Update](../../core/state/state.go) 的 `PromptCount` 按 `PromptSubmitted` 回调递增，只用进程内 mutex；没有原生 ID 去重和跨进程读改写保护。不能直接把它当成新增周期功能的可靠时钟。
- [session claim](../../core/state/dedup.go) 的键含 gen、按需 epoch、rule 和渲染后模型正文哈希，各挂载点共享；`O_EXCL` 保证同一键只有一方胜出，cap-drop 可以释放。它本身没有过期回合。
- [动态 system](../../core/plan/system.go) 已支持 session.start/prompt.submitted 双挂载；静态 system 和缺静态槽位的单入口回退需要区分。refresh 不能留在静态位置，也不能静默退回仅启动一次。
- [engine](../../core/engine/process.go) 先判 block 优先，再抢占、按上限释放；[snapshot](../../core/state/snapshot.go) 严格枚举并校验旧 seen 文件；[stats](../../core/state/stats_read.go) 严格读取既有字段。新增状态不能绕过这些路径。
- agenthooks 已归一化两家的不透明回合 ID：[Codex codec](../../agenthooks/codec_codex.go) 的 turn_id 和 [Claude codec](../../agenthooks/codec_claudecode.go) 的 prompt_id。本稿不把 ID 当可相减的数字，不增加协议解析器。

基线定向回归 307 条 pass、0 fail/skip；8 项独立探针证明既有跨点评估共享 claim、释放后重试、逐回调计数、compact、resume、clear、正文改变及子作用域行为。它们只确认旧行为，没有验证未来实现或重现跨进程 lost-update；后者是由进程内锁边界识别的风险，须在 A9 新建受控多进程测试。

## 2. 规则入口及合法组合

建议增加规则字段 `refresh: N`，也允许出现在包级 `defaults` 与 `from` 覆盖中。只接受整数 0–1,000,000；省略或 0 关闭，0 可取消继承值；null、bool、字符串、负数、小数和超限值报 `refresh-invalid`。解析、合并、目录/单文件包与 schema 一致，不静默取整。

```yaml
defaults:
  repeat: session
rules:
  - id: review-reminder
    target: system
    refresh: 5
    reason: 长会话里周期提醒评审约定
    text: 本仓库的评审意见需要给出文件位置。
```

`N > 0` 只适用于最终 `action: inject | warn`、`repeat: session` 的运行时规则。warn 的默认 repeat 仍是 every，作者须显式设置 session（或继承 defaults）。block、repeat every/turn、event subagent.start、system replace 均报 `refresh-incompatible`；native 上显式写 refresh（包括 0）仍报 `native-field`，继承的普通 defaults 对 native 仍不生效。

system、event、tool、mcp、skill 可按上述组合启用。含 refresh 的 system 即使正文静态、没有 when，也走动态 session.start 与 prompt.submitted；不能同时写入静态槽位。其他 target 只在原本的匹配点补发，不新增定时器，不把工具规则移到 prompt，也不借 refresh 放宽 when、sources、agent 或输出能力。

对 inject，启用 refresh 且没有有效 reason 时也给 T007，提示周期重复的成本；reason 只消告警，不进入模型。关闭 refresh 后不新增诊断，也不改变旧 defaults、repeat 或静态判定。

## 3. 回合时钟

refresh 使用每个 `(实际 state 根, harness, session_id, agent)` 的独立整数 `q`，只由 STYLE 实际收到的 `prompt.submitted` 推进。startup/clear 的新生命周期从 0 开始；工具调用、skill.explicit/UserPromptExpansion、模型切换、compact、resume、subagent.start 都不加回合。它不是模型响应次数、API 请求数或自然语言对话轮数。

同一生命周期中，有非空原生回合 ID 的 prompt 首次出现时 `q += 1`，持久登记 ID 摘要与序号；相同 ID 的并发或迟到重放复用原序号，不再递增。后续工具事件若有已登记 ID，使用该 ID 的原序号，不能让旧回合事件借用较新的 q 提前补发。ID 只存 SHA256，不保存提示或工具内容。

缺原生 ID 时，每个 prompt 回调计一次，工具沿用当前 q；explain/plan 披露 `prompt-count-fallback`。这时无法辨认重复回调或迟到工具，不承诺原生 ID 级幂等，也不拿提示正文哈希冒充 ID。只有工具事件提供了尚未登记的原生 ID 时，不推进 q，不允许基于它触发周期到期；普通首次命中仍可发送，并从当前 q 建立基线。

没有任何 prompt 的作用域保持 q=0，只能正常首次发送，不能用工具数量推进周期。子 agent 独立计数；某 harness 不给子作用域 prompt 时，不承诺该子作用域周期补发。Claude 的后台消息等若实际产生 UserPromptSubmit，照样计入，报告必须用“提交回合”而非“用户手写消息”。

该时钟与旧 `scope.json.prompt_count` 分开持久化；后者及旧 repeat:turn 的语义保持。只有当前 harness 的有效 index 包含 refresh 时才启用新增计数、锁和状态 I/O；无 refresh 安装继续旧路径。

## 4. 首发、间隔与正文变化

补发周期按**上一次保留输出的同一模型正文**计算，不按固定整除窗口，也不按第 N 次命中计算。正文和规则的识别与既有 repeat 一致；warn 用最终模型渠道的正文，只有用户渠道时沿用既有空模型正文的键语义。

对同一 gen、按需 epoch、rule、模型正文 bh 与 N，记录上次保留的 q 为 `last`：

1. 尚未发送且没有旧 session claim：按原规则首次命中立即抢占、输出，保存 last=q。
2. 有 last 且 q-last<N：重复不发；迟到事件 q<last 也不发，不能令游标倒退。
3. q-last>=N：在下一次 selector/when/sources 均满足的原评估点抢占一次，输出后 last=q。即使跨过多个周期也只发一次，不累计欠账。
4. block 优先、空输出、未命中和 cap-drop 都不能消费补发机会。释放本次占位时还原旧 last，不把它误算成已发。

例如 N=3，启动时 q=0 首发；提交回合 1、2 不发，3 补发，6 再补发。同一回合有十次工具调用仍只发一次。若 q=3 时条件不满足，直到 q=7 才命中，则在 7 发一次，下次最早 10；不是连续补四份。

动态正文 A→B 时，B 没有 claim 就立即首发；A→B→A 时，旧 A 按自己的 last 决定，不能因为切回来而清空去重。哈希仍使用既有渲染后正文口径，周期不进入正文，不追加时间、回合号或包装标题。

## 5. 生命周期与升级基线

| 情况 | refresh 时钟与 claim |
|---|---|
| startup | 当前 scope 新生命周期，q=0；清除其旧 refresh 状态，与既有 seen 清理同步 |
| clear | gen 改变，新的 q=0；旧代不能匹配，新代按 sources/原评估点首发 |
| compact 且 reinject_on_compact=true | q 不变，epoch 改变；新 epoch 可立即补发，随后从本次 q 重新计算间隔 |
| compact 且 reinject_on_compact=false | q 与 last 保持，不因 compact 强制首发；原 sources 过滤仍有效 |
| resume | q、last 和去重记录保持；resume 本身不计回合，也不绕过 sources |
| fork | 新 session_id 是新作用域；复用同一 scope 时保留状态，不读取/复制父作用域状态 |
| 子 agent / 另一项目 / 用户范围 | 独立 state 根或 agent，互不推进或消费周期 |
| 无 refresh 的旧 scope 首次启用 | 新时钟从 0 计起；若同一正文已有普通 session claim，只建立 last=当前 q，不马上重复，满 N 个新观察回合后才补 |

周期 N 参与新增策略身份。改到尚无 cursor 的 N 时，已有普通 session claim 作为保守基线，满 N 个新观察回合后才补；改回已有 N 则复用原 cursor。关闭后以相同 N 重启用也复用原 cursor，若已经到期，下次匹配可以补一次；没有任何 refresh 的期间不推进新增时钟，也不事后重建那段历史。新正文仍可正常首发。所有保留输出也保留/建立普通 session claim；去掉 refresh 后继续普通 session 去重，不把历史注入忘掉。卸载和替换跨包保留方继续沿既有规则身份边界，不新增别名去重。

## 6. 状态、并发与故障

保留 session.json、scope.json、旧 seen 文件及其严格 schema；新增状态放在 scope 下独立 refresh 命名空间，格式为 1。逻辑内容包含时钟/代、原生 ID 摘要到 q 的收据、按策略与正文分开的 last，以及可撤销的本次 reservation 身份。具体 Go API 和文件拆分由 T40 落实，但读写必须有边界、严格解码、拒绝 symlink/非法类型/溢出，且 snapshot 的总 16 MiB/10,000 文件边界不能被绕过。

当有效 index 启用 refresh 时，使用按 state 根/session 分开的跨进程锁（harness 在 refresh 数据内隔离），保护 state 更新、时钟去重、engine claim、cap 释放与本次最终状态；同一 session 的共享 model/effort 更新也在该锁内，agent 的时钟和游标仍分开。锁须由 OS 在进程退出/崩溃时释放，不用“超时即删除 O_EXCL 锁文件”抢锁。取得锁前后核对根和文件身份；不能 unlink 正在使用的锁 inode。接口由 STYLE state/runtime 协作，平台实现不进入 agenthooks codec。

锁等待最多 20ms，并受更早的请求取消/deadline 限制；超时/锁不支持/坏状态为 state-error，按现有 runtime/codec 策略处理，不绕过锁补发，不猜测或自动重建游标。Windows 对应实现由 D11/T70 落实前不宣称可用；非受支持平台在 plan/doctor 明确说明。T40 必须测量新增路径的实际进程成本，继续现有 p95 目标。

抢占仍在输出前。cap-drop、合并前失败等可恢复路径在同一保护下释放本次 cursor 和 session 首次 claim；不能删掉先前成功 claim，也不能撤销别人的更新。落盘失败不得输出尚未成功占位的文本。进程在占位成功后崩溃，可能损失这次补发，接受和旧 repeat 相同的先占位取舍；不承诺跨文件掉电原子或原生投递确认。

snapshot 必须在原有只读/双重捕获边界内包含时钟、收据和 cursor。有新增 refresh 状态时先只读打开已存在的 session 锁，在最多 20ms/请求 deadline 内取得读保护，并核对锁 inode；锁缺失、忙或身份漂移则明确失败，不能趁写事务中间捕获。锁内仍做双重文件捕获；锁文件本身不作为重放内容，不在源根创建锁或修改时间。无新增状态的旧 snapshot 保留旧捕获方式。explain 在私有根运行同一时钟/claim 路径，包含 seed 的状态与全部新增字节限额；不得扫描真实 transcript 或写真实 state。清理由现有冷路径负责，hook 不扫描或清理历史目录。

## 7. plan、预算、explain 与 stats

plan 的有效规则说明增加可选 refresh 信息：间隔、提交回合计数、按同正文上次保留输出计算、只在原匹配点补发，以及缺 ID/子作用域的限制。无刷新字段时文本/JSON 不新增空字段；install/update/sync/trust 的效果比较和 native/replace 披露边界保持。

system refresh 需要可评估的 prompt.submitted 才能维持周期：start 与 prompt 都支持时双挂；只有 prompt 可用时按原 fallback 规则披露动态降级；只有 start 时不能承诺周期，degrade/skip 均明确跳过 refresh 规则，error 拒绝安装。工具类若只能静态降级，不能把 refresh 丢掉后声称支持；按同样不可实现策略处理。事件类则保留作者所选入口，并报告“到期后等待该事件”，不暗加订阅点。

Claude 除实际输出事件外，还必须在存在任何有效 refresh 规则时订阅 UserPromptSubmit 作为时钟输入，即使没有 prompt 规则；同时订阅 SessionStart 的全部生命周期来源以维护时钟/代/纪元，输出规则仍独立经过 sources 过滤。这个 clock-only 入口默认无输出，也计入 probe/doctor 的真实订阅检查。Codex 复用固定订阅面。原生事件映射、handler 渲染与 owner/信任仍由 agenthooks 完成，STYLE 不复制协议。

T001、T003 和运行时硬上限仍按一次输出的全文估算，不把正文除以 N；always_on 按既有 placements 分类，跨包折叠后再算联合成本。相同正文但 refresh 不同、启用/关闭不同或完整 placement 不同不能跨包折叠；相同完整策略才可沿 M2 规则保留一方。周期只解释潜在频率，不给总会话 token 或账单保证。

explain trace 对 refresh 条目增加可选对象，记录 N、当前 q、旧 last、时钟质量和 initial/seeded/not-due/due/clock-unavailable/cap-release 等安全原因；repeat-key 摘要包括新增策略身份，旧条目 trace 不变。明确区分编译折叠和运行时未到期，不输出正文、原生 ID 或私有路径。

stats.jsonl 字段和 result 集合保持：保留输出记 output，未到期记 dedup，容量丢弃记 cap-drop；实际保留的每份正文均计入原估算。刷新输出不伪装成另一个业务动作，历史 reader/预算口径兼容。精确的到期理由通过 explain 查询，stats 的 output 仍是 runtime 输出尝试，不证明 harness 接收或模型投递。

## 8. 编译与旧安装兼容

源码 schema 增加可选 refresh；只有最终有效 runtime 条目启用 `N>0` 才生成 **index format=2**，entry 增加整数 refresh。新版 engine 读取 format 1/2，format 1 不得夹带该字段；没有有效 refresh 的包/安装继续生成 format 1，旧 golden 原样。全包任何 harness 启用 refresh 时，整份 index 都为 2，不声称老 runner 能部分读取其他 harness。

采用显式格式门槛，避免旧 runner 忽略新语义。T40 用本基线真实二进制验证 format 2 按已有失败策略拒绝（旧 stderr 仍可能只提示 sync，不能改写旧程序行为）；新版 doctor/文档须明确先升级已配置 runner 再 sync，不借此新增 fail-closed。旧管理命令的 strict schema/批准结果不兼容也必须拒绝且无写入，不静默删除 refresh 再编译。

lock 的 1/2/3 和项目 declaration/binding 的现有格式不因 refresh 升号；它们继续绑定完整编译效果、原生 surface 与声明摘要。修改 refresh 是规则效果变化，需要普通管理路径及既有信任确认；frozen 只重现原锁效果，不把旧批准升级成新策略。无 refresh 的旧安装/index/state、所有旧路线与新 clone 采用的保守规则保持。

build/explain.json 的可选说明与 index 2 同事务生成，包含安全周期元数据并绑定实际 index 摘要；坏/缺可选说明仍按 D1 降为 index-only。安装、重编译、卸载和五条路线的批准/漂移/回滚必须一起验证，不能只给 engine 加字段。

## 11. 建议一起确认的产品选择

1. **按上次发送计算间隔**：`refresh: 5` 表示首次命中就发，之后同一正文隔满 5 个提交回合、下次符合条件时再发；0 关闭，不补欠账。只与 session 去重搭配，system 自动转动态。
2. **只数实际收到的提交回合**：工具调用不算；有原生 ID 就识别重复，缺 ID 如实按回调计数；压缩仍由 reinject_on_compact 决定是否立刻补发。独立 state 和跨进程保护支持五条现有路线。
3. **新能力显式升级，成本照全文算**：只有启用 refresh 才写 index 2，旧规则/旧 state 保持；旧 runner 明确拒绝新格式，预算不因间隔而打折。
