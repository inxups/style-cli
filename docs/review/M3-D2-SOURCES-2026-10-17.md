## 2. 来源表达与命令

### 2.1 输入语法

保留现有目录和 `*.style.md` 本地输入。新增显式 `git+https://host/repository.git`；不猜测裸 HTTPS URL、GitHub 简写、scp/SSH 或 `git://`。本轮生产 CLI 不开放 file、HTTP、ext、自定义 helper、带凭据 URL；本地 Git 和 loopback/TLS fixture 仅通过测试注入端口使用。需要私有仓库、代理或 SSH 的用户继续先自行取得本地目录；这项首次支持范围须在评审中确认。

- `--ref` 只接受完整 `refs/heads/<name>`、`refs/tags/<name>` 或与 object format 对应的完整 commit OID（SHA-1 40 位、SHA-256 64 位小写十六进制）。不接受短 ref、短 hash、reflog、range、`~`/`^` 等 revision 表达式。规范 ref 仍须通过 Git ref 格式校验。
- 省略 ref 时，解析远端符号 HEAD，保存其规范 branch ref 和本次 commit；HEAD 不能解析到唯一 branch 时要求显式 ref。tag 必须 peel 到 commit，指向其他对象则失败。
- `--path` 为仓库相对路径，默认 `.`；目录须包含 STYLE.yaml，单文件须以 `.style.md` 结尾。拒绝绝对路径、空段、`.`/`..` 段（唯一根 `.` 除外）、反斜线和控制字符；不做 glob 或 shell 展开。
- Git URL 去掉 `git+` 后持久化，scheme/host 规范化，保留路径大小写、转义和 `.git`/尾斜线语义；拒绝 userinfo、query、fragment。来源标识不保存凭据，报告转义不可信文本。
- 本地路径不接受 `--ref`/`--path`；Git 来源不接受 `--link`。现有 `./目录` 等本地路径语义不变。

### 2.2 拟新增入口

以下为已定稿语法；Git validate/plan/install 与 update 已实现，install --frozen 已由 T22/A5 实现验收。安装/validate/plan 共用来源解析，只有实际安装需要批准。

```sh
style validate git+https://example.invalid/team/styles.git --ref refs/tags/v1 --path packages/review
style plan git+https://example.invalid/team/styles.git --ref refs/heads/main --path review.style.md --harness codex
style install git+https://example.invalid/team/styles.git --ref refs/tags/v1 --path packages/review --harness codex --yes
style update terse-reviewer --yes
style update terse-reviewer --ref refs/tags/v2 --yes
style update --all --yes
style install --frozen --yes
```

validate/plan 的 Git 输入可取得并保留私有来源缓存，但不改变已装包、lock、approved、settings、index、路线或信任；原有本地输入的只读保证继续有效。普通 install 的披露和 `--yes` 约定不变。

update 必须指定一个包名或 `--all`，不能同时使用，也不默认更新全部。`--ref` 仅可对单个 Git 包改追踪目标；URL/path/包类型的切换不在本命令范围。接受既有 `--yes`、`--allow-replace`、`--json`，不新增隐式 settings、路线或 harness 覆盖。

frozen 不接位置来源，读取当前 STYLE_HOME 的整份锁；不新增 `--lock`、路径重定位或项目级安装语义。与 `--harness`、`--route`、`--set`、`--link`、`--ref`、`--path`、`--fail-closed` 互斥，保留 `--yes`、`--allow-replace`、`--json`。

## 3. Git 取得与缓存

### 3.1 取得过程

app 的来源端口将请求转换为 `ResolvedSource`：规范来源身份、选择后的 tree/blob 身份、不可变文件字节与摘要。core/spec.LoadSnapshot 继续只消费目录/单文件模式、文件 map 和诊断标签；不启动 Git、不联网、不读取用户 Git 配置。

1. 检查可信 Git executable 及所需能力，记录版本；缺 Git/能力不支持给明确错误，不回退为本地路径。当前调查版本为 2.54.0，未据此宣称其他版本全部兼容。
2. 先取得远端广告中的 HEAD/规范 ref/OID 与 object format，再建立相同 object format 的私有临时 bare 仓库，按捕获的完整对象 OID 取得；显式 commit 也只能取得该 OID。广告后分支移动、对象不可达或服务端不允许取得该 OID 都失败，不改取新的 tip。不 checkout、不初始化 submodule、不执行 LFS、安装脚本、filter、textconv 或仓库 hook。取得客户端不读取用户/系统 Git 配置，不采用宿主 insteadOf、credential helper、askpass、proxy 或任意 `GIT_*` 注入；仅保留明列的运行环境和系统 TLS 校验能力。
3. 协议默认禁止，生产仅显式启用 HTTPS，禁止重定向和交互凭据；保留证书校验。使用参数数组与 `--`，不经 shell。禁止替换对象、递归 fetch 和自动维护；不借用已有仓库的 config/alternates/promisor 数据库。错误输出有界处理，不将原始 Git stderr、远端提示或环境变量写入用户报告/日志。
4. 将所选 ref peel 为 commit 后，所有读取固定该完整 OID。用 `ls-tree -z` 解析对象模式、OID 和原始路径，再用不带 `--filters`/`--textconv` 的 `cat-file` 读取 blob。不能以 `git archive` 替代：export-ignore/export-subst 可改变归档内容。
5. 仅遍历选中的目录或单文件；该范围内的 symlink（120000）、gitlink（160000）、特殊/不规范/控制字符路径及大小写折叠碰撞均拒绝。仓库其他未选目录不作为包输入。普通文件的 executable bit 不保留为本地执行权限；包文件以 0600、目录 0700 写入。
6. 沿用本地快照忽略 `.git`、`.hg`、`.svn`、`.DS_Store` 的约定；`.gitattributes` 是普通数据文件，不解释其导出或换行指令。目录包收集全部剩余普通文件，再交给原有 UTF-8/NUL/256 KiB、包格式、注册表、native、模板和预算门禁。

新增 Git 输入每个导出最多 1,024 个文件、合计 16 MiB，每个文件沿用 256 KiB；取得总时限 60s，并响应调用方更短的取消期限。Git 输出与对象枚举须边读边限额，stderr 最多读取 64 KiB 后丢弃余量；不得先把无界流整体读入内存。该时限不是远端仓库总下载字节保证，磁盘空间/写入失败按取得失败处理；T20 必须有中断、资源耗尽及清理证据。

### 3.2 缓存边界

只持久保存已完整导出的源码快照，不复用可变远端 tracking refs 或仓库配置：

```text
STYLE_HOME/cache/sources/git/v1/<source-key>/manifest.json
STYLE_HOME/cache/sources/git/v1/<source-key>/files/...
```

source-key 为规范 URL、object format、commit、包路径/类型的无歧义编码 SHA256；manifest format=1 保存同一身份、selected object、逐文件 SHA256 与内容聚合摘要。ref 仅是查找策略，不代替 commit。成功导出后才发布完整缓存，目录 0700、文件 0600；半成品不可命中，并发发布要复验已有完整条目。

每次命中都验证 manifest、身份及文件摘要，拒绝 symlink、逃逸、额外文件和损坏内容。普通 validate/plan/install/update 可重新取得并修复损坏缓存；frozen 不取得、不修复缓存。未批准的预览可留下有效来源缓存，不能留下半安装；取消只清本次临时仓库/暂存内容，不删其他命令的条目。没有新增对源仓库脚本的授权。

## 4. 锁文件和兼容

### 4.1 格式选择

Git 首次成功落盘时将整份 lock 升到 format=2，新版同时读 1/2。纯本地 format=1 的生命周期继续写 1；已为 2 的非空 lock 不自动降级，最后一包卸载仍按旧流程移除锁。失败、取消、只读预览和 frozen 均不升级或重写锁。

不把 Git 元数据塞进 format=1 的可选未知字段：现有 YAML 解码会忽略未知字段，旧写入器可能丢掉来源。format=2 让旧版 decodeLock 明确拒绝；需用真实旧二进制验证该管理兼容边界。普通 runtime 继续消费 format=1 index，不读 Git 来源或发起取得。

### 4.2 Git 包记录

保持包的 name/version/seq/files/settings/replace/approval，以及所有 harness 绑定。source.kind 继续使用 `dir`/`file` 表示存储模式；Git 的 source.path 为规范仓库包路径，source.link 与 package.link 均为 false。新增 source.git：

| 字段 | 必需含义 |
|---|---|
| url | 不带 git+ 的规范 HTTPS URL，无凭据/query/fragment |
| ref | 规范 branch/tag 或完整 commit selector；默认 HEAD 已转换为 branch |
| object_format | sha1 或 sha256，决定 OID 长度与校验 |
| commit | peel 后的完整 commit OID |
| object | 所选目录 tree 或单文件 blob OID |
| content_sha256 | 按现有路径排序聚合算法计算的 sha256: 摘要 |

files 仍保存包相对路径的逐文件摘要；单文件使用其来源 basename，安装到现有 `<name>.style.md` 管理位置。每个摘要为 `sha256:` 加 64 位十六进制。聚合输入逐行是 `path + NUL + per_file_hash + LF`，和现有 packageLockHash/hashPackageFiles 相同。Git OID 与这个内容摘要分开；ref/commit 变了而文件没变，仍须在预览与锁中反映来源变化，index 的 package.lock 内容身份无需变化。

format=2 对 Git 字段、URL、ref/OID、路径、kind/link 组合、逐文件摘要和聚合值做严格校验，禁止来源字段缺失或自相矛盾；不能只改 commit 文本冒充新内容。保留包转换、clone、sync/trust、卸载和写锁共用同一保真编码，不能丢掉 Git 记录。未知新格式继续拒绝。

同名 Git 重装仅在规范 URL、ref、commit、path、kind、字节、settings 和安装选择一致时幂等；不能沿用“本地不同来源但内容相同即已安装”的判断吞掉来源变化。已有同名包的来源转换须明确卸载/重装，不暗中改追踪源。

Git 管理副本是固定 commit 的导出内容。对它的手工编辑不得通过 sync/trust 再批准为同一个 commit；检查报 `git-snapshot-changed`，恢复锁定内容可使用 frozen，开发修改可另行走本地/link 来源。list/doctor 显示安全来源身份和漂移；这些命令及普通 hook、explain、probe 不因此联网。

## 5. update 的授权与事务

### 5.1 选择和候选

update 默认预览；有变化而未确认时给完整报告并沿用 awaiting_confirmation/退出 1，`--yes` 才应用本次候选。无变化返回 0，不写任何安装文件。取得过程可预热 §3 缓存，报告明确区分缓存活动与安装改变。

| 来源 | 选中后的新输入 | 固定边界 |
|---|---|---|
| Git branch/tag | 重新解析 lock.ref；或单包显式 --ref | 本次解析后固定完整 commit；tag 移动也披露；不按包 semver 自动找“最新” |
| Git commit | 使用已锁 OID；显式 --ref 才换目标 | 没有更新时无变化；不可把不可达旧 commit 替换成分支 tip |
| 本地复制 | 重新捕获原 source.path | 不把手改 packages 副本当作上游更新；源缺失/类型改变失败 |
| 本地 link | 捕获原链接源的当前字节 | 明确选择及确认可批准普通/native 改动和首次 link 信任；仍完整披露 |

名称必须保持，版本须有效但不要求递增；同版本内容变更、版本降低、revision-only 变更分别披露。保留 seq 和已有 settings 值，删除已不声明的键，新键仅采用包中声明的 default；缺必填值失败，提示先按现有配置流程补齐，不从别的包或环境取值。新增 replace 仍须 `--allow-replace`，多 replace、预算、requires 和 fallback:error 继续阻止安装。

选中的复制/Git 管理副本若已偏离锁，先失败并提示恢复或既有本地 trust 流程，不能覆盖用户尚未批准的编辑。link 的当前字节本身是选中候选，提交前也须核对未在捕获后变化。

### 5.2 未选包与能力披露

未选包只使用经 lock.approval 验证的批准字节；没有批准文件时，只有能完整证明旧批准表示的兼容路径才可继续，否则明确报缺基线。即使 link 已有普通自动同步授权，update 也不采用其未选新字节。不能循环调用 trust/sync，借此扩大选择范围。

将选中候选与未选批准快照一起完整编译、去重和预算检查；路线仍按 lock 绑定。预览包含来源/ref/commit/版本、增删改文件、渲染差异、native 完整披露、settings 键变更、replace、预算与路线效果。值和命令正文只出现在用户主动查看的批准披露中，不进入摘要日志或常规诊断。

采用保守边界：若重编译使未选包的批准渲染/native 表示改变，报 `update-unselected-effect` 并列出包名，要求显式 `--all` 或先单独处理相关包。跨包去重归属变化也适用；不悄悄重写未选 approval。这样不会借本次更新接受未选包的 settings/native 或新的执行效果。`--all` 的确认覆盖所有候选和实际联合效果，任一来源失败则整批不安装。

### 5.3 捕获与应用

一次调用只解析 ref、捕获来源/settings/锁和生成候选一次；完整 detached preview 通过后应用同一候选，不能在确认后再取移动中的分支或重读源码。两次 CLI 调用（先预览，后加 --yes）分别产生候选，后一次必须重新展示实际应用的来源/摘要；前一次预览不构成跨调用的固定授权。

app 增加仅覆盖提交阶段的共享管理写入 guard，install/update/sync/trust/uninstall 的同版写入都须加入；网络与等待确认期间不持有 guard。沿用 OS 身份检查，busy 明确失败；回收陈旧 guard 必须核对 PID/出生身份，不能只按时间删除。它协调合作进程，不宣称能排除同用户恶意替换或旧版不合作进程。

持有 guard 后先核对捕获的 lock、包、approval、settings、index/说明和每个目标配置的 Before/身份/模式，再应用全部包交换与 agenthooks 文件计划；任一步失败逆序恢复已变更文件与包，并报告任何回滚失败。未选包文件和 settings 不改；所有成功的选中包、approval/settings、index/explain、lock、hook/static 作为一个管理事务验收。每文件 rename 与应用期错误回滚不承诺多文件全局原子或断电恢复；异常终止留下的漂移必须由后续只读检查识别，不能报成功。

guard、候选及回滚编排由 app 负责；agenthooks 保留配置格式、owner/trust 合并和文件 ApplyFiles。T20 先接入共享提交保护与 Git 安装，T21 再扩展多包协调；不得为 Git 绕开现有 Before 或归属检查。

## 6. frozen 的重现边界

### 6.1 入口与不变量

`style install --frozen` 对当前 STYLE_HOME 的非空 format=1/2 锁重建全部包与派生产物，锁的精确字节保持不变。它是已有安装/备份的离线恢复入口；只有一份 lock、没有所需源字节/settings/批准记录时不能成功，不声称跨机器、跨根、跨 harness 版本可移植。项目/云端的重定位留给 D3。

不解析远端 HEAD/ref、不启动 Git、不联网、不写来源缓存，也不从可变分支或包版本猜测内容。保留 name/version/seq/link 信任、来源、settings 键、harness/config_dir/route/version/fail_closed/static_layout 及批准摘要；不调用 Detect、不接受新路线选择、不自动迁移旧静态布局。当前可执行文件/路线绑定及渲染结果必须仍满足锁，差异给 build/binding 错误。

### 6.2 内容和批准基线

| 来源 | 可用内容 | 缺失或偏离时 |
|---|---|---|
| 复制目录/单文件 | 逐文件摘要完全匹配的管理副本、lock.approval 验证的源字节，或原路径的精确匹配快照 | 仅原路径变化可忽略，只要有其他完整锁定快照；无完整内容则 frozen-content-unavailable |
| Git | 上述已锁管理/批准字节，或身份/commit/object/content 全匹配的完整导出缓存 | 不要求缓存必须存在；其他内容可用即可。只有损坏/不匹配候选且无可验证快照则失败，不 fetch |
| link | 原 source.path 的实时内容逐文件匹配，且已存在 link_trusted | 变化、路径缺失或首次信任都失败；不以旧批准副本掩盖活链接已改变 |

一个包只能选取一份完整快照，不拼接多份候选的零散文件。捕获后再次使用私有字节，不产生路径竞态；必要的源/目标 symlink、额外文件、摘要或格式错误不能绕过现有校验。

settings 值仍从现有私有 settings 文件读取，不写入锁、不采用新 default 或环境覆盖；缺文件/必填值、未声明键或键集合与锁不符都失败。必须有可验证的批准表示，重新编译得到的 approval（源字节、有效渲染、native）与 lock.approval 精确对应。旧 format=1 缺 approval 等必要基线时给 `frozen-metadata-incomplete`，先经正常 install/sync/trust 建立；旧的普通生命周期不因此失效。格式 0/隐式旧格式不作为完整 frozen 输入。

旧锁没有 settings 值摘要；frozen 验证的是当前值生成的已批准效果，不声称锁认证了未使用 settings 的原始值。现有锁也不保存编译器二进制摘要，重复性验收固定同一二进制；输出相同不能证明换版 runtime 的全部语义相同。锁文件本身不是签名，不能防同用户同时篡改锁和批准文件。这些限制均须出现在使用说明。

### 6.3 重建与确认

复用锁定 adapter 与包校验/联合编译，核对逐文件摘要、版本/名称、Git 聚合值、surface/rendered/trust/static_files 与批准表示，不能重写锁来掩盖编译器、二进制路径、设置或绑定差异。旧布局需要迁移时明确失败，走正常管理流程后再 frozen。

在这些约束下，可恢复缺失或损坏的管理包副本，以及缺失的 index/explain 等可推导产物；hook/static 配置恢复仅在现有 owner 计划允许时进行，外来同名文件、被用户修改的托管块或损坏归属仍拒绝。不能凭 lock 强占文件。整个锁的重建使用 §5.3 同一提交保护和事务，lock 本身作为只读前置条件核对。

仍披露 native/能力并要求 `--yes`；replace 沿用既有授权，锁定内容含 replace 时须显式 `--allow-replace`。没有实际安装变化返回 0；有恢复计划而未确认返回 awaiting_confirmation/1；失败保全既有内容和锁。不会清理 runtime state、stats 或 probe 收据，不把投递/信任/模型计数写成已成功。

## 7. 报告与失败结果

已有 validate/plan/install 报告保持原字段含义，Git 来源增加可选 source 元数据（kind/path、规范 URL/ref/object_format/commit/object、content_sha256、cache_hit），不显示原始 Git 命令/stderr。cache_hit 是取得说明，不是安装授权或输出确定性的组成部分。

update 与 frozen 的新报告使用 format=1、command、status（unchanged/confirmation-required/applied/error）、selected、changes、reports、diagnostics、awaiting_confirmation；frozen 另报告 lock_sha256 与 locked_source=true。changes 按既有 seq 排序，包含 before/after 安全来源、version、内容摘要、file/rendered/native 差异和 settings 键变化；错误不伪造 after。完整成功/失败 JSON 为单份；用法解析失败 stdout 为空，普通状态/错误不混入 hook wire。

| 情形 | 稳定诊断族 | 结果 |
|---|---|---|
| 非法来源/选项/ref/path、缺 Git/能力 | source-invalid / git-unavailable / git-capability-unsupported | 退出 1，安装不变 |
| ref 不存在/不可达、TLS/协议/超时/限额/取消 | source-fetch-failed / source-limit / canceled | 退出 1，清本次暂存，无半安装 |
| 源文件/缓存/锁无效 | source-invalid / source-cache-invalid / lock-invalid | 退出 1，不将取得成功当校验通过 |
| Git 管理副本修改、未选批准效果改变 | git-snapshot-changed / update-unselected-effect | 退出 1，列恢复或显式选择步骤 |
| frozen 缺元数据/内容、源变化、输出不匹配 | frozen-metadata-incomplete / frozen-content-unavailable / frozen-source-mismatch / frozen-build-mismatch | 退出 1，锁不变，无联网回退 |
| 未确认、busy、旧计划/文件变化、回滚失败 | confirmation-required / management-busy / installation-changed / rollback-failed | 退出 1；恢复不完整须明确报告路径和结果 |
| 现有 fallback:error / T003 预算阻止 | 沿用现有阻止诊断 | 退出 4，安装不变 |
| 无变化或已批准计划应用完成 | unchanged / applied | 退出 0 |

T20 沿用既有管理 CLI 错误格式：捕获输入漂移实际报告 `management-input-changed`，lock 格式错误保留原有读锁错误文本；包与文件回滚错误合并报告，并保留恢复失败的备份路径。表中的 installation-changed/lock-invalid/rollback-failed 是分类名称，不表示既有命令已改为 update/frozen 的新报告 schema。T21 的 update 结构化状态已实现并通过 A4；T22 frozen 结构化状态已实现并通过 A5。

退出 3 继续只表示既有 sync 等待 trust。诊断字段转义控制字符，常规日志不存源正文/settings 值/native 命令/凭据。结构化报告和批准预览按现有私有内容边界处理。
