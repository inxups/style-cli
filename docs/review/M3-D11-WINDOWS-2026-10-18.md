# M3-D11 Windows 支持边界定稿

日期：2026-10-18；基线 `2ddb678269a071eb72d2d8f50b93df8ae4635ce6`。依赖 T60/A16，按用户全部评审通过授权定稿；Windows 真实 harness 的 W1 已由用户延期，Windows CI 不延期。

## 支持范围

Windows 10/11 与 Windows Server 的 amd64/arm64 Go 原生二进制保留通用 validate/plan/count/explain、包与锁管理、runtime、refresh 和 stats。M3 Windows 的集成入口限定为 Codex user 与 Claude Code user；两个 harness 使用原生 style.exe，不能把 npm 的 cmd/bat shim 当作 STYLE runner。项目与插件路线的可移植启动器另需设计，Windows 上 available/plan/install 必须明确拒绝，不生成 POSIX 启动器；macOS/Linux 的全部既有路线保持。

这是平台支持契约，不把未实现路线或交叉编译记作成功。Windows 上作者 native command 仍按既有 POSIX 边界拒绝，并按正常 fallback 规划；不猜作者脚本属于 cmd、PowerShell 或 Git Bash。外部用户的 native hook 和其他 owner 配置仍须保留。D10 四字段和扩展拒绝规则不变。

## 启动、归属与协议

Claude 保持 command/args exec form，要求 style.exe，不需要 shell 引用。Codex 的 command 字符串通过 由 GetSystemDirectory 固定绝对路径的 Windows 自带 powershell.exe（不从项目 cwd/PATH 或环境变量寻找 shell；系统目录含 shell 特殊字符时保守拒绝） 的 NoProfile/NonInteractive/EncodedCommand 调用原生二进制；参数先按 Windows argv 规则引用，再把 FileName/Arguments 作 PowerShell 单引号字面量转义并编码 UTF-16LE/base64，使空格、Unicode、反引号、百分号、感叹号和 shell 元字符不被外层 cmd/Git Bash 再展开。固定脚本启用终止错误，通过 System.Diagnostics.ProcessStartInfo 继承原始 stdin/stdout 句柄并传播子进程 ExitCode；不用 PowerShell 的 native 参数重序列化或文本管道；异步参数必须在编码前加入。

owner 识别只解码本库固定前缀且合法有界的启动器，再按既有独立 argv 标记检查；不能因运行器编码而失去卸载归属。Codex trusted_hash 继续计算最终 command/timeout/matcher，不能改 hash 算法。Windows CI 用真实 powershell.exe 和测试子程序逐字节校验 Unicode stdin/stdout、参数边界、退出码与元字符不执行；这证明启动器，不代表真实 harness 已接受定义。

协议、事件映射、输出白名单、配置合并/恢复和信任归 agenthooks；CLI 的 Windows 路线可用性和存储准备归 adapter/app，core 不增加 harness 名条件。

## 路径、身份、权限和文件事务

路径使用 filepath 和 os.Root，拒绝设备名、ADS、非本地分量、驱动器相对路径及逃逸，盘符/Unicode/空格/长路径进入原生 CI。会话分量在 Windows 使用摘要以避免设备名与大小写碰撞；已有 POSIX 存储不重写。Windows 不承诺网络共享或不支持 ACL/硬链接的卷；实际根目录重解析点仍按既有约束拒绝。

进程身份增加内核 GetProcessTimes 创建时间与父 PID，不用命令输出猜 PID 复用。可执行文件身份同时绑定卷/文件 ID 与既有规范路径、大小、模式和时间；探针承认真实 exe，不能用 POSIX 执行位判断。

Windows 的 chmod 不提供 0600/0700 隔离。私有管理/探针存储建立受保护 DACL，仅当前用户、SYSTEM 和 Administrators；通过打开的句柄校验实际 DACL 与文件身份，不能用跳过模式检查伪造私有性。创建的文件先私有化再写；既有探针记录仍校验，失败不接纳租约或收据。POSIX 继续原有模式约束。外部配置保留 Windows 可表达的只读属性及原始字节；不宣称复原任意外部 ACL。

refresh 用 LockFileEx/UnlockFileEx 对永久空锁文件的一个字节做共享/独占非阻塞锁，保留 20ms 预算、上下文取消和进程退出释放；禁止按 stale PID 删除活锁。仍检查目录、锁文件身份和临时文件替换。事务保持同卷暂存、flush/close、校验后 rename、失败回滚；只读目标、占用句柄或不支持的文件系统必须报错并保全/恢复，不承诺断电时多文件原子性。

Git 子进程沿用显式参数、隔离配置、上下文超时和 250ms 管道等待。Windows 当前只保证终止直接 Git 进程和有界返回，不承诺 Unix 进程组式后代清理；不允许据此运行任意作者 shell 或 credential helper。此限制在平台指南披露并由取消用例核对。
